# Architecture / 架构

## 数据流

1. 浏览器把选题、目标读者、语气、补充要求和是否保存草稿发送给本地服务。
2. `pipeline` 校验输入并调用演示生成器或配置的内容模型。
3. `render` 把结构化文章转换为适合公众号的 HTML。
4. 封面生成完成后，文章、HTML、封面和阶段记录写入独立输出目录。
5. 只有使用者明确选择且关闭演示模式时，`wechat-service` 才上传封面并调用微信新增草稿接口。
6. 最终发布仍需使用者进入公众号后台审核并操作。

## 主要模块

- `src/server.js`：HTTP 接口和静态页面。
- `src/pipeline.js`：生成状态机、落盘和失败恢复。
- `src/openai-service.js`：结构化文章与封面生成适配层。
- `src/wechat-service.js`：微信令牌、素材上传和草稿创建。
- `src/queue.js`、`src/scheduler.js`：本地选题队列和定时执行。

## 设计原则

- 人工审核优先：生成不等于发布。
- 本地优先：演示和产物检查无需外部账号。
- 失败可恢复：记录最后成功阶段，草稿上传可独立重试。
- 凭据隔离：密钥只从环境变量读取，不写入网页或产物。
